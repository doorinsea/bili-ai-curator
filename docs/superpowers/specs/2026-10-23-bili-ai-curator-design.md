# B站 AI 内容筛选与评论推荐助手设计

日期：2026-10-23

## 1. 目标

创建一个单账号、单人使用的本地 AI B站助手。它使用独立的 B站实验账号在后台扫描指定领域内容，用 DeepSeek 判断视频质量与相关性，每天最多选出 5 条值得推荐给主人的视频，并在对应视频评论区真正 `@` 主人的主账号。

第一阶段只支持 B站，不发送私信，不自动关注、点赞、收藏、投币或修改个人资料。

## 2. 非目标

- 不自动注册 B站账号。
- 不代保存或同步主账号 Cookie。
- 不绕过验证码、风控、平台限制或访问控制。
- 不批量运营多个 B站账号。
- 不自动私信陌生人。
- 不自动发布视频或动态。
- 不保证平台接口长期兼容。

## 3. 运行边界

- 运行环境：当前 Windows 电脑。
- 程序在 Windows 当前用户登录后启动。
- 电脑关机或睡眠时任务停止；恢复运行后从持久化状态继续。
- B站登录通过 `bili-cli` 扫码完成。
- B站 Cookie 由 `bili-cli` 保存到 `%APPDATA%\bili-cli`。
- DeepSeek Key 从本地配置或环境变量读取，不写入仓库。
- 默认活跃时段为北京时间 `09:00-23:30`。
- 每日额度按北京时间零点重置。

## 4. 内容范围

关键词包括但不限于：新模型、大模型、DeepSeek、Claude、ChatGPT、Gemini、Qwen、Kimi、Agent、RAG、多模态、视频生成、AI 编程、本地模型、推理模型。

默认新鲜度窗口：最近 7 天。

### AI 二创

关键词包括但不限于：DeepSeek 大肥鱼、DeepSeek 拟人、Claude 二创、ChatGPT 二创、Gemini 拟人、Qwen 拟人、Kimi 拟人、AI 动画、AI 小剧场、AI 整活。

默认新鲜度窗口：最近 30 天。

### 绝区零

关键词包括但不限于：绝区零、版本更新、角色 PV、剧情、式舆防卫战、危局强袭战、配队、攻略、数值分析、高能操作。

默认新鲜度窗口：最近 14 天。

### 崩坏：星穹铁道

关键词包括但不限于：崩坏星穹铁道、星铁、版本更新、角色 PV、剧情、配队、攻略、模拟宇宙、虚构叙事、末日幻影、高能操作。

默认新鲜度窗口：最近 14 天。

### 无畏契约

关键词包括但不限于：无畏契约、VALORANT、新特工、新地图、新皮肤、职业比赛、高光、战术讲解、复盘。

默认新鲜度窗口：最近 7 天。

特别高热或高信息量的视频可放宽至默认时间窗的两倍，但不能超过 30 天。

## 5. 内容发现

通过 `bili-cli` 的 JSON 接口执行：

- 首页推荐流
- 综合热门与分区排行
- 搜索结果
- 相关 UP 主的最近投稿
- 热门、每周必看等辅助入口

同一视频从多个入口出现时增加来源权重，但只生成一条候选记录。

## 6. 两级筛选

### 基础过滤

- 主题关键词命中或语义分类命中
- 发布时间在对应时间窗
- 播放量达到相对同龄视频的基础门槛
- 视频未处理过
- UP 主未在当天重复推荐
- 评论区可用
- 不包含明确排除词

### DeepSeek 评分

输入：

- 标题、简介、标签、分区
- 字幕或转写文本
- 章节
- 热评摘要
- 画面总览图描述
- 发布时间和播放、点赞、收藏、评论数据

评分维度：

| 维度 | 权重 |
|---|---:|
| 主题匹配度 | 30% |
| 内容有趣或有信息量 | 25% |
| 同发布时间桶内的播放排名 | 20% |
| 点赞、收藏、评论率 | 10% |
| 新鲜度 | 10% |
| 来源多样性 | 5% |

播放量必须按发布时间分桶比较，例如 6 小时、1 天、3 天、7 天、30 天。禁止只用绝对播放量排序。

每天初始使用严格质量线。随着时间推移可以有限度降低门槛，但不得低于配置中的绝对最低质量线。

## 7. 评论策略

每天最多发布 5 条推荐评论，成功发布后才消耗额度。

每条评论包含：

- 针对视频内容的具体反馈
- 真正 `@` 主账号
- 简短、自然的大肥鱼人设
- 不包含链接
- 不重复使用固定模板

当天第一条推荐评论以时间相关问候开头，例如：

> 早上好，新的一天又开始了。

问候按实际时间使用早上好、下午好或晚上好。

第五条推荐评论最后追加：

> 今天的大白饭吃完了，等明天有饭吃再给主人推

评论生成后先执行 `dry-run` 和本地规则检查，再调用真实评论接口。

## 8. 发表节奏

- 两条成功评论至少间隔 20-45 分钟，具体值随机。
- 同一 UP 主每天最多推荐一条。
- 同一视频永久只评论一次。
- 新账号前 48 小时只扫描和评分，不发表评论。
- 预热后按 `1 条/天 -> 3 条/天 -> 5 条/天` 渐进开放。
- 默认活跃时间外不发表评论。

## 9. 停止与告警

### 连续低质量熔断

连续 10 个通过基础过滤并实际交给 DeepSeek 评分的候选视频低于最低质量线时：

- 停止当天继续扫描。
- 找最近一个允许评论的候选视频。
- 发布一次状态评论并 `@` 主账号：

> 今天刷到的视频都太一般了，没有值得推荐的 @主人

重复视频、评论关闭、接口错误和风控异常不计入连续 10 条。状态评论每天最多一条，不消耗推荐额度。

### 余额不足

DeepSeek 返回余额不足或明确认证失败时：

- 立即停止继续调用模型。
- 停止当天扫描。
- 尝试在最近的可用视频下发布一次：

> 今天没饭吃了，DeepSeek 余额不足，我先停止找视频了 @主人

### 风控与验证码

出现 `risk_control`、验证码、限流或评论权限异常时：

- 立即停止全部写操作。
- 不重试评论。
- 不尝试绕过平台限制。
- 记录错误并等待用户处理。

## 10. 数据存储

使用本地 SQLite：

- `videos`：视频身份、分区、UP 主、发布时间、统计数据
- `evaluations`：主题分类、评分、推荐理由、模型名
- `comments`：评论正文、评论 ID、发布状态、是否折叠
- `daily_state`：扫描次数、连续低质量数、已推荐数、停止原因
- `events`：登录失效、风控、余额不足和普通错误

所有写操作同步记录到 `data/audit.log`。

## 11. 配置

本地 `config.json` 至少包含：

- 主人 UID
- DeepSeek API 配置
- 每类内容的关键词、排除词、时间窗和权重
- 最低质量线
- 每日最大推荐数
- 活跃时间
- 评论最小间隔
- 预热阶段
- `dry_run`
- 风控暂停时长

不在仓库中保存真实 Cookie 或 API Key。

## 12. 错误处理

- 单条视频读取失败：跳过并继续。
- 字幕缺失：使用章节、热评和画面总览；需要时转写。
- `bili-cli` 返回非零：记录标准错误，不把失败算作成功。
- 评论结果未知：标记待回读，不立即重试。
- 评论被折叠：不重复发布，只记录并停止当天继续写入。
- 数据库写入失败：以保守方式停止，不继续外部写操作。

## 13. 测试

### 单元测试

- 主题分类和排除词
- 发布时间分桶与播放排名
- 互动率与新鲜度评分
- 每日 5 条上限
- 第五条特殊后缀
- 首条问候
- 连续 10 条低质量熔断
- 余额不足熔断
- 去重和同 UP 主限制
- `@` 格式校验
- 风控状态机

### 集成测试

使用保存的 `bili-cli` JSON 样本测试完整评分和评论生成流程，不访问 B站。

### Live dry-run

真实读取 B站数据，但所有写命令强制带 `--dry-run`。

### 首次真实发布

在用户明确授权后，仅对一条视频发表评论并验证回读，成功后才进入渐进开放。

## 14. 交付阶段

1. 项目骨架、配置和 SQLite 状态模型
2. 内容发现与 DeepSeek 评分
3. 评论生成、熔断和审计
4. 自动化测试与本地 dry-run
5. 首次真实评论演练
6. Windows 登录后自启动
7. 创建 GitHub 仓库并推送不含凭据的代码

## 15. 风险说明

本项目依赖 B站非公开接口和 `bili-cli`。平台规则、接口签名和风控策略可能变化。自动评论属于高风控写操作，新账号尤其容易触发限制。项目不会规避验证码、风控或平台限制；遇到此类状态必须停止并交由用户处理。
